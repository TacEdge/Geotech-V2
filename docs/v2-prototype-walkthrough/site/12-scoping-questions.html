12 · V2 Technical Scoping Questions

Configure · Capture · Confirm — the current prototype, interpreted against the V2 Product Definition.

A curated set of questions the prototype raises, grouped to help the Technical Lead focus the 30-hour scoping sprint. These are not answered here unless the Product Definition or prototype clearly resolves them.

01 · Offline & sync

What is the offline-first capture model, the two payload classes (record vs media), and the conflict policy? This is the single largest technical risk and is not represented in the prototype.

02 · Review-state implementation

How is the submit → confirm → reopen machine implemented, with a single-owner rule per state, operator edit-lock, and audit trail?

03 · Confirmed-only-outward

How is outward visibility gated so only confirmed records reach the engineer/contract, and re-open withdraws them until re-confirmed?

04 · Work-type configuration

What is the runtime shape of a work-type declaration (required stages, fields, completion criteria, report format)? Is V2 scoped to anchoring + piling or all six?

05 · Work-item identity

System identifier vs human reference (e.g. B17): how is identity assigned, and what keys off it externally?

06 · Data model

Entities (project, zone, work type, work item, stage record, finding, evidence) and the invariants — how are they persisted?

07 · Spatial model

Image-relative positioning of work items; the geolocation coordination-readiness seam.

08 · AI-assisted workflows

Plan-import (PDF → planned items) and test-record extraction: the propose → human-approve → commit contract.

09 · Findings & computation

Where are system-computed variances (depth, grout) calculated vs operator-declared exceptions?

10 · Permissions

Role → permission model; how “publish to field” and read-only engineer access are enforced.

11 · Reporting & closeout

Per-type report formats; assembling reporting/closeout from the live confirmed record.

12 · Files & evidence

Evidence model (polymorphic parent, provenance), thumbnails, offline media sync.

13 · Application architecture

The V2 stack: the prototype is dependency-free static HTML; V2 needs a real application + data layer. Migration from the legacy V1 codebase.

14 · Deployment

Hosting, environments, build + release for a real application (prototype deploys to GitHub Pages).

15 · Security

Auth provider, attributable sign-on sessions, credential handling.
